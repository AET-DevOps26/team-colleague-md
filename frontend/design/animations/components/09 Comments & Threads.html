Reduced motionExtended

Coverage
Reply expand · stagger · show-more · new-comment slide — all collapse
Retained
Composer's box-shadow crossfade (state change must remain visible)
Why
The information conveyed by motion (which comment is new, which thread expanded) is still available via background tint on §7 and class swap on §6

Side-by-side: full-motion left, reduced-motion right. Click the buttons to retrigger.

Full motion
Reduced motion

The @media (prefers-reduced-motion: reduce) rule at the bottom of the stylesheet kills the animations on every primitive in this file at once. The composer's shadow crossfade is the only animation preserved — it's a state-change indicator, not a flourish.

React hint

<CommentList>
<CommentList items={...} stagger={true} />. Stagger is a render-time prop — only true on first mount. useThread() exposes insert(comment) which triggers §7's slide-in.
<CommentThread>
<CommentThread parent={c} replies={[...]} />. Holds the §6 grid-row trick internally; exposes showMore().
<ReplyComposer>
Inline reply input. CSS-only entry via animation: fadeIn 180ms. Auto-focuses on mount; submit-disabled until non-empty.
<Composer>
The bottom-bar composer. focused state class controls §3's expand. Outside-click collapses only when empty.
useThread()
const { insert, like, reply } = useThread(threadId). insert emits an item with a fresh: true flag for 800ms so §7's tinted bg can read it.
useReducedMotion()
The CSS query handles all four animations in this file. Only consult the JS hook if a higher-level component (e.g. a modal-confirm-on-submit) needs to skip its own choreography.
