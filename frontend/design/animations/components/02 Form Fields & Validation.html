Error shake · 320ms 5-keyframe

Trigger
fires once on submit-error · never on keystroke validation · never on blur
Curve
0% · 20% (-6px) · 40% (+6px) · 60% (-4px) · 80% (+4px) · 100% — symmetric decay
Pair
error message slides in (160ms · opacity + translateY) after shake completes — the order matters
Master
C03 noted modal-level .auth-modal.shake is unreachable in production · C02 plumbs it at field-level so the React contract matches the user's mental model (one wrong field, not the whole modal)

Submit the empty form to fire the shake. The message reveal runs after the shake settles — overlapping the two reads as anxious; sequencing them reads as deliberate.

Password
Please enter your password

5 keyframes · max travel ±6px · the curve is intentionally slightly under-damped so the rest position reads as a settle, not a snap. Reduced motion collapses the shake to no movement; the message still reveals.

Extended · proposed for <TextField status="success" />

Success tick · 240ms stroke draw

Order
border swaps to --success · then 60ms later the tick draws (stroke-dashoffset 22 → 0 over 240ms)
Why 60ms
the gap lets the eye land on the green border before the tick draws — without it both motions read as one snap
Use
async validation pass (e.g. username check, email-domain ping) — single field at a time

Click "Validate" to fire the success state. The tick draws inside the field-box itself, replacing the eye-icon position.

Username

A single 22-unit dasharray covers the path's actual length — the tick stays crisp because the line never has to interpolate sub-pixel widths during the draw.

Password eye · cross-fade morph

Idle (hidden)
open eye glyph at full opacity · scale 1
On (visible)
closed (slashed) eye glyph · cross-fade 140ms · scale 0.85 → 1 over 200ms
Why morph
production uses one open-eye SVG that toggles input.type with no glyph change — the user has to guess state from the input · a 2-glyph morph eliminates that guess

Click the eye icon to toggle visibility. The two SVGs cross-fade with a slight scale so the change is decisive but not noisy.

Password

No flip, no rotation — both glyphs are eye-shaped, and a flip would suggest the eye flips physically rather than the visibility state changing. Action: when <PasswordField /> lands, replace the existing single-glyph eye in pages/Verita Auth.html with this 2-glyph morph.

Character counter · 240ms color shift

Idle
color --text-tertiary
Warn
≥ 80% of limit → --warning · 240ms ease-out
Danger
≥ 100% → --danger · 240ms · field-box border swaps in parallel
No size change

Type into the textarea — the counter shifts to amber at 80% and red at 100%. The field's border picks up the danger color when over-limit, but the input keeps accepting characters so the user can see what they're cutting.

123 / 160

Limit set to 160 on the demo so the warn/danger thresholds are easy to reach by typing. Production limits will vary per field — the React contract takes warnAt (default 0.8) and maxLength, and computes the rest.

React hint

<TextField>
props: label, placeholder, size: 'sm' | 'md' | 'lg' (34/38/44), variant: 'auth' | 'meta' | 'topbar' | 'admin', status: 'idle' | 'error' | 'success', floatingLabel (boolean, Extended)
<PasswordField>
extends <TextField> · adds showToggle (default true) · 2-glyph morph on toggle · auto-clears reveal on blur if autoClearOnBlur
<Textarea>
variants: composition (borderless title/body) · standard (bordered) · adds showCount, maxLength, warnAt for the counter color shift
<SearchField>
icon-prefixed wrapper around <TextField> · adds onClear · variant: 'topbar' uses 4px ring · variant: 'admin' uses 3px ring
useFieldValidation()
returns { status, error, shakeKey, validate, reset } · increment shakeKey to fire one shake · validation runs on submit, not on every keystroke
