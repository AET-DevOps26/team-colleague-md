Production's primary tag-filter primitive. Pure text chips: no fill, no border, no underline. Single-active by design — clicking a chip swaps which item carries .active. Click any chip to see the color + weight swap in isolation.

Note: in production this row does not filter the masonry — it is a navigation-style category row. Real filtering (with masonry exit motion) is an Extended-tier proposal — see §8.

Filled/outline cross-fadeExtended · Primary

Proposal
Unified <TagChip> contract — single component for any toggleable tag
States
off: --bg-surface + --text-secondary + 1px --border-default
on: --text-primary bg + white text + matching border
Motion
background 160ms ease-out, color 160ms ease-out, border-color 160ms ease-out
Why 160ms
Slow enough to read as a state shift; fast enough that batch-toggling 3–4 chips doesn't feel sluggish
Why same dimensions
Off and on share padding + border-width — only colors swap. No layout shift, so neighbors don't reflow.

The unified primitive production has not codified yet. Click any chip to toggle — multiple can be active at once (multi-select), unlike the topbar's single-active row. Hash glyph (#) carries its own color transition for visual depth without bleed.

Why not a bounce on toggle? A bounce would lie about the action — toggling a tag is a passive filter selection, not a celebratory event. Save bounce for true successes (like-on-post, see C12).

Count-badge incrementExtended

Proposal
Subtle scale bump when a count value changes in place
Trigger
Add .is-bumping on value change; remove after 240ms
Keyframes
0% scale(1.0) → 35% scale(1.1) → 100% scale(1.0) · ease-out
Why 1.1, not 1.2
11px text — bigger peaks read as a glitch at this size. 10% peak is enough to draw the eye without being noisy.

Click "Increment" to bump the count. The badge stays visually anchored (transform-origin: center) and only scales — no color shift, no slide. Reduced-motion fallback skips the bump entirely; the value still updates instantly.

Chip removeExtended

Proposal
Symmetric collapse on dismiss — geometry and opacity fade together
Sequence
Click × → .is-leaving applied → 220ms collapse → DOM removal
Properties
max-width · opacity · padding · margin all transition 220ms ease-out
Why max-width, not width
Real chip widths vary with label length. max-width animates from the actual content width down to 0 without measuring.

Each chip has an × dismiss. Click it to see the collapse — width and opacity ease together, neighbors slide left to fill the gap. Click "Restore all" to reset.

Filter applied stateExtended

Proposal
Multi-select highlight communicating "this chip is in the active filter set"
Distinct from §4
§4's on/off is a discrete chip-level toggle. .is-applied here is a filter-set membership indicator: chips can be applied, hovered, or off independently.
Visual
8% accent tint bg · 38% accent border · accent tick glyph slides in (width 0 → 12px)
Motion
160ms ease-out on bg, color, border, tick width — all in parallel

Click chips to add/remove them from the filter set. The accent tick reveals on apply, retracts on remove. Useful when the filter set persists across pagination (e.g. Search Results filter pills).

Masonry filter exitExtended · pairs with C05

Proposal
When a filter chip removes cards from the feed, slots fade + scale-out before reflow
Why here, not C05
C05 owns hover and entry; filtering removes cards, which is a chip action. C05's deviation explicitly delegates this motion home.
Sequence
Click filter → matching slots get .is-hiding → 220ms exit → JS adds .is-collapsed → grid reflows neighbors
Motion
opacity 1 → 0 + scale(1) → scale(0.97), both 220ms ease-out — same timing as C05's .cover shadow for vocabulary parity

Six placeholder slots tagged with category labels. Click a category to hide matching slots; click "Show all" to bring them back. Neighbors reflow after the exit completes, so you see the full 220ms before the grid collapses the gap.
