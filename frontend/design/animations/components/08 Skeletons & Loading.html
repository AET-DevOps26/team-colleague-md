Skeleton + shimmerProduction · Primary

Source
pages/Verita Search Results.html · lines 291–304, render at lines 619–637
Markup
.skeleton base + size modifiers (.skel-cover, .skel-line.w100|w80|w60|w40)
Trigger
Search Results resultsState === 'loading' swap; renders 8 mock cards
Motion
animation: shimmer 1.4s ease-in-out infinite — opacity pulse, no gradient

The only skeleton primitive in production. A flat --bg-elevated rectangle that pulses its opacity. Six widths (w40–w100) compose into card silhouettes. The cover variant uses aspect-ratio: 4/3; mock-text-card variants drop the cover and use a 160px placeholder.

Production caveat: shimmer is opacity-only. On a low-contrast surface it can read as content fading out and back in, not as "loading." Extended §4 swaps in a left-to-right sweep that reads more clearly as activity.

Reading progressProduction

Source
pages/Verita Post Detail.html · lines 750–762; identical block in Verita Digest Post.html · 472–477
Markup
.reading-progress > .reading-progress-bar — 2px fixed strip
Trigger
scroll event reads scrollY / (docHeight - viewportH); sets style.width
Motion
transition: width 60ms linear — a touch of smoothing, not enough to lag the cursor

Determinate read-position bar. Scroll inside the stage to see it fill. The 60ms width transition is intentional: instant feels twitchy, anything longer feels disconnected from the input.

The long read

This stage scrolls. As you drag the inner scrollbar, the 2px --accent bar at the top fills proportionally. Production renders this against position: fixed; top: 0;, so on the real page it sits above the topbar.

Notice the 60ms width transition: too fast and a fast scroll wheel makes the bar twitch in stair-steps; too slow and the bar feels like it's pulled by a rubber band. 60ms linear is the sweet spot.

Production reads scrollY and document.documentElement.scrollHeight. Here we measure the inner scroller instead so the demo isn't tied to the page's own scroll position.

The bar is unnoticed when you're reading; it is a peripheral aid for re-orienting after a scroll jump or browser back.

Long-form Verita posts treat this as the only motion above the article — sticky engagement bar comes in later, fade-down on scroll.

Reduced motionExtended

Status
Governance section; full coverage handled by one CSS rule at the bottom of the stylesheet
Coverage
Shimmer · sweep · spinner · pull-to-refresh — all collapse simultaneously
Retained
Determinate progress fill (instant width updates instead of 240ms ease)
Why
State change must still be conveyed; only the motion is suppressed

Left column shows full-motion variants. Right column simulates the prefers-reduced-motion: reduce output: shimmer becomes a static tinted block, the spinner becomes a solid dot, the sweep stops mid-frame.

The rule lives at the bottom of this file's stylesheet: a single @media (prefers-reduced-motion: reduce) block kills the animations on every primitive in this file at once. The progress bar's state change is preserved (color flip on success); only the timing is collapsed to instant.

React hint

<Skeleton>
<Skeleton variant="line|cover" width="60" />. Default animation="pulse" matches production §1; animation="sweep" picks up §4. Same 1.4s period.
<Spinner>
<Spinner size={14|24} tone="default|on-accent|on-dark" />. The dark-surface variant covers the production §2 case via tone, not via a separate primitive.
<ProgressBar>
<ProgressBar value={0..100} status="filling|success|error" />. status="success" handles the §6 color crossfade. indeterminate={true} would defer to <Spinner>.
<ReadingProgress>
<ReadingProgress target={ref} />. Reads scrollY from target (defaults to document.documentElement); renders the §3 fixed bar.
<PullToRefresh>
<PullToRefresh onRefresh={async() => …} />. Consumes drag events; threshold defaults to 56px. Mobile-only; renders nothing on desktop.
useLoading()
const { isLoading, started } = useLoading(promise). Returns started as the wall-clock timestamp so callers can decide between "show spinner immediately" and "wait 200ms before showing anything" (no-flicker fast loads).
useReducedMotion()
Returns boolean from matchMedia('(prefers-reduced-motion: reduce)'). Per §8, prefer the CSS media query — only consult the hook when geometry has to differ (e.g. pull-to-refresh threshold could be raised so accidental drags don't trigger).
