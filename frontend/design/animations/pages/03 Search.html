Skeleton → result fade Production

Type a query and press Enter — the skeleton mounts immediately and shimmers (opacity 1 → 0.45 → 1, 1.4s ease-in-out infinite) while the fake fetch resolves. On resolve, skeletons unmount and result cards fade in with the same 180ms / 60ms stagger pattern as P02 comments. Shimmer keyframe is verbatim from pages/Verita Search Results.html:292–296.

Hook: useSearchResults(query) returns { status, items } where status ∈ {idle | loading | ready | empty} — bind status to the area's render branch.

Result list stagger Production

Same canonical @keyframes fadeIn as P02's comments — 180ms ease-out, opacity + translateY(4px → 0), 60ms per-item delay. Cap stagger at 6 items so a 50-result query does not run a 3-second cascade. The keyframe is the page-level animation vocabulary's "list arrival" tempo; do not invent a second one for search.

Empty state reveal Extended

When status === 'empty', the empty panel reveals with a 220ms opacity + translateY(6px → 0) ease-out — slightly slower than result cards (180ms) so the "no results" beat lands deliberately rather than ghosting in like a missed render. Production today renders the empty state with no entry motion (Search Results.html:670); this proposal adds the reveal.

Filter chip toggle Production

Filter pills sit below the results header. Toggling a chip uses the C06 §4 cross-fade — 160ms ease-out across background, color, and border-color with shared dimensions so the row never reflows. On chip change, the result list re-mounts through the same skeleton → fadeIn cycle as Section 1; the chips themselves do not animate the cards.

In production, chips are static text (no toggle). The cross-fade lives in C06 §4 as the unified <TagChip> contract; P03 is its first page-level consumer.
