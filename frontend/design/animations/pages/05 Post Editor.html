Toolbar tooltip Production

The editor toolbar is the only surface in the product where tooltips ship today. .tb-btn-tip is an accent-fill ink pill positioned bottom: calc(100% + 6px) with translateX(-50%) centering. Pure CSS — transition: opacity 100ms triggered by parent :hover. No delay, no transform, no scale. The 100ms instant fade is intentional: this is a confirmation cue (yes, this button is Bold), not an explanation, so loud-and-immediate is correct here.

Hover any button. Tooltip is the production primary tooltip (C07 §1). For ambient navigation tooltips (sidebar collapsed labels, icon-only nav) use the Extended hover-delay variant in C07 §4 instead — different intent, different tempo.

Meta-input focus ring Production

The metadata strip below the body (Subtitle, Tags, Source URL) uses .meta-input 1:1 from pages/Verita Post Editor.html:335. 38px height, 8px radius, --bg-surface rest → #fff on focus, plus a 3px rgba(10,10,10,0.06) shadow ring. Three properties co-transition over 120ms: border-color, background, box-shadow. Distinct from the inline modal-field family (no bg-flip there) — see C02 §3 vs §5 for the surface-context split.

Tab into either field, or click. The 3px shadow is the widest part of the focus expression — it carries the affordance even when border-color shifts are subtle on the cream surface.

Inline modal — Add link Production

Toolbar Link / Image actions open a 320px modal hosting .modal-field inputs. Backdrop fades in (160ms ease-out), panel scales 0.97 → 1 with translateY 8px → 0 (180ms ease-out, see C03 §1). Modal-field inputs are 36px / 7px radius / 3px shadow on focus — visually similar to .meta-input but with no bg-flip, since the modal is already on a white surface; flipping would be redundant chrome.

Save state morph Extended

Production today routes save state through the topbar .status-pill (idle / saving / saved) — a passive indicator next to the publish button. This Extended proposal keeps the status pill but adds an active confirmation on the publish/save button itself: 240ms morph from "Save" label → checkmark scale-in (160ms, 80ms delay) with the button background fading from --accent → --success. After 1400ms the button reverts to the idle "Save" label. Why morph instead of toast: the action and confirmation share a surface, so the user's eye doesn't need to track to a corner toast to verify the save landed.

Total cycle: 240ms morph in → 1400ms hold → 200ms revert. Reduced-motion fallback collapses to a 120ms color swap and instant checkmark — same information, no transform.
